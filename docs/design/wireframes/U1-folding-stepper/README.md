# U-1 创建订单 · 折叠式分步 wireframe（低保真）

> 关联：`docs/prd/PRD-001-family-companion.md` §F7
> 日期：2026-05-29（W19 D5）
> 产出人：凝光（PM）
> 预览：浏览器打开同目录 `index.html`（三页并排：① 服务选择 / ② 医院搜索 / ③ 确认下单）

## 一、设计原则（与 PRD §F7 对齐）

1. **四步同屏可见**：服务类型 → 医院 → 日期 → 患者&陪诊师确认，垂直堆叠，全程不离开同页
2. **当前步展开 + 已完成步显结果**：已完成步只显结果行（"全程陪诊 · ¥299"），点击可回改
3. **回改下游不重置**：除非字段冲突（如改医院后原选科室不存在）；冲突需弹确认
4. **双端字段/步骤/文案一致**：见 §三 契约表，作为 develop done 互锁

## 二、步骤组件三态

| 态 | 视觉 | 行为 |
|---|---|---|
| `collapsed`（未到） | num 灰底 / 标题灰 / 右侧 "未选择" | 点击无响应（除非 done） |
| `active`（当前） | num 主色蓝底 / 展开 body / sticky 底部"下一步"按钮 | 编辑中 |
| `done`（已完成） | num 绿底 ✓ / 右侧显示摘要 / 整行可点 | 点击回改：弹"是否回改？下游已选数据将保留" |

## 三、跨端字段契约（与 PRD §6 AC#13 互锁）

| 项 | 取值 | 互锁要求 |
|---|---|---|
| 步骤数 | **4** | 微信/iOS 完全一致，不可拆分或合并 |
| 步骤命名 | 服务类型 / 医院 / 日期 / 患者 & 陪诊师确认 | 完全一致 |
| 服务选项 | 全程陪诊 ¥299 / 半程陪诊 ¥199 / 代办跑腿 ¥149 | 价格、名称、排序一致 |
| 摘要文案模板 | 见下方「摘要模板钉死表」 | 双端模板字符串**逐字符一致**（AC#13 必测） |
| 巨字号模式（PRD §F5） | 见下方「巨字号缩放表」 | 双端 token **完整一致**，非仅按钮 |

### 摘要模板钉死表（W20 D1 定型 · 双端逐字符一致）

| 步骤 | 模板 | 变量格式（钉死） | 示例 |
|---|---|---|---|
| ① 服务类型 | `{服务名} · ¥{价格}` | 服务名取选项原文；价格为整数无小数 | `全程陪诊 · ¥299` |
| ② 医院 | `{医院简称}` 或 `{医院简称} · {科室}` | 科室**可选**：选了才拼 ` · {科室}`，未选则只显医院简称，**不显「· 未选科室」** | `市一院` / `市一院 · 神经内科` |
| ③ 日期 | `{YYYY-MM-DD} {周X} {上午\|下午}` | 日期固定 `YYYY-MM-DD`（补零）；星期固定「周X」（周一…周日，**非「星期X」**）；时段仅「上午」「下午」二选一 | `2026-06-03 周三 上午` |
| ④ 患者&陪诊师 | `{患者首字}** · {关系} · {年龄}岁` | 姓名脱敏：仅首字 + 两个 `*`；年龄整数 + 「岁」 | `张** · 母亲 · 68岁` |

> 分隔符统一为半角空格包裹的全角圆点「 · 」（U+00B7，两侧各一个半角空格）。两端实现取此表为唯一真源，禁止各自格式化。

## 四、状态机（创建订单）

```
[Step1 active]
  ↓ 选服务 → 「下一步」
[Step1 done] + [Step2 active]
  ↓ 选医院（+科室可选） → 「下一步」
[Step1 done] + [Step2 done] + [Step3 active]
  ↓ 选日期/时段 → 「下一步」
[Step1-3 done] + [Step4 active]
  ↓ 确认患者+陪诊师 → 「提交订单」
[提交] → 收银台
```

**回改路径**：任意 done 步骤可点击 → 该步重新 active、其余 done 保持 → 用户确认后保留下游已选值。

**回改冲突判定（钉死 · 给胡桃明确规则）**：
- **下游字段定义**：步骤序号大于被改步骤的字段即为下游。仅「② 医院的科室」存在跨步冲突可能；日期、患者与医院选择无强依赖，回改医院**不重置**日期/患者。
- **科室冲突规则**：科室为**可选**字段。回改医院后——若原未选科室 → 无冲突；若原选科室在新院区科室列表中**仍存在** → 保留；**不存在** → 清空科室 + 弹 toast（见 §五），其余下游字段不动。
- **冲突检测位置**：前端在「确认回改」时即用已加载的新院区科室列表做本地校验给出 toast；后端在提交订单时做**最终一致性兜底校验**（防止前端绕过），二者规则同源。

## 五、错误/边界态（W20 D1 给出高保真补充）

| 场景 | 处理 |
|---|---|
| 缺失字段提交 | 「提交」置灰；点击置灰按钮自动滚动到第一个未完成步并展开 |
| 回改导致冲突（如改医院后原科室不存在） | 弹 toast「原科室"神经内科"在该院区不可用，已为您清空，请重新选择」 |
| 网络失败（医院列表/陪诊师匹配） | 该步 body 内显示空态 + 「重试」按钮，不阻断其他步骤 |
| 巨字号模式 | 整页字号、按钮、间距等比放大；步骤摘要超长以两行截断 + "…" |
