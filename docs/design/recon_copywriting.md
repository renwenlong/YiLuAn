## 统一原则

为保证对账工作台文案在运营、财务、合规同学之间的统一与易读，所有新增文案需遵守以下规则：

1. **避免英文术语** —— 凡是可中文化的词均使用中文表达；如 `diff` → 差异、`mismatch` → 不平账、`pending` → 排队中、`fail` → 失败。
2. **避免缩写** —— 不在界面直接使用 `T+1`、`Q3`、`AR/AP`、`autofix` 等缩写；如必须保留行业缩写，须配合中文全称（例：`T+1`「次日」）。
3. **使用业务语言** —— 以业务流程视角组织文案：用"工单 / 关单 / 复核 / 平账 / 台账"而非"job / close / sign / diff / ledger"。数据库字段名（如 `wallet_ledger`、`recon_id`）严禁直出到界面，必须经字典转译。
4. **关键操作配 hover 提示** —— 涉及"撤销 / 关单 / 强制平账 / 触发合规守卫"等不可逆或高权限操作，必须配 hover 浮层说明：
   - 操作含义（一句话业务描述）
   - 影响范围（影响哪些工单 / 是否触发审计）
   - 是否可回滚
5. **状态色 + 文字双通道** —— 告警 / 异常状态不仅靠颜色（红黄绿）传达，必须搭配明确的中文状态词，便于色弱同学与黑白截图沟通。
6. **时间表达本地化** —— 所有时间使用「年-月-日 时:分」中文格式，避免 `T+1 09:00 UTC` 这类技术化时间串。
