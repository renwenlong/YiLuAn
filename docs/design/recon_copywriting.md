# 对账工作台运营文案改写稿 v0.1

> Action #7 — admin H5 对账工作台（reconciliation worklist）面向运营人员的文案优化建议。
>
> **背景：** 晨会 Design 反馈，当前对账工作台的文案沿用研发术语（如 "diff 平账"、"T+1 cron"），运营同学在日常使用时存在理解门槛，影响处置效率。本稿先提交一版改写建议，待 Design / 运营评审后落地到组件。
>
> **盘点状态：** 当前仓库中 `admin-h5/` 目录尚为静态页骨架，对账工作台对应的 `pages/recon/*` 组件尚未提交（研发预计在下个迭代实装）。下表"出现位置"为基于产品需求文档与原型稿推测的预期路径，待页面落地后回填实际组件路径。

## 统一原则

后续所有对账工作台（含告警、邮件、企微通知）的运营向文案，请遵循以下四条原则：

1. **避免英文术语**：UI、提示、告警一律使用中文；确需保留英文时（如品牌名、外部系统名），首次出现给出中文译名并在括号中保留英文。
2. **避免缩写**：禁止 "T+1 / cron / diff / autofix / Q3 / KYC" 等研发或行业缩写直接暴露给运营，统一改写为完整业务表达（"次日 / 定时任务 / 差异 / 自动修正 / 季度 / 实名核验"）。
3. **用业务语言**：以"运营完成什么动作 / 系统发生了什么业务事件"为视角描述，禁止暴露数据库表名、字段名、技术栈名词。
4. **关键操作配 hover 提示**：所有涉及资金、关单、回滚、合规的操作按钮与状态标签，必须配置 hover / tooltip 详细说明（"系统会做什么、需要谁来做、做完会怎样"），降低误操作风险。
