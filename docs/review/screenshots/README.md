# 微信小程序审核截图终稿规划

> **总目标**：为微信小程序审核准备 5–8 张关键页截图终稿。本目录为「截图清单 + 拍摄要点 + 命名规范 + 占位文件」，Design 接到任务后只需**按清单拍 + 替换占位文件**即可。

---

## 命名规范

```
screenshot-NN-<page-key>-<device>.png
```

- `NN` —— 两位数字编号（01–08，与下方清单一致）
- `<page-key>` —— 页面短标识（kebab-case），与下方清单一致
- `<device>` —— `iphone14p`（iPhone 14 Pro，6.1"）或 `iphone15pm`（iPhone 15 Pro Max，6.7"）

**示例**：`screenshot-01-home-iphone15pm.png`

---

## 推荐设备

| 优先级 | 设备 | 屏幕 | 截图分辨率 |
|---|---|---|---|
| 主推 | iPhone 15 Pro Max | 6.7" | 1290 × 2796 |
| 备选 | iPhone 14 Pro | 6.1" | 1179 × 2556 |

> 微信审核对分辨率无硬性要求，但需清晰、未压缩、未加水印；优先用主推机型。

## 隐私脱敏清单（强制）

凡截图中出现下列任意字段，**必须**使用测试数据：

| 字段 | 真实数据 | 测试占位（建议） |
|---|---|---|
| 手机号 | 用户真实手机号 | `138****0001` 或 `188 0000 1234` |
| 姓名 | 用户真实姓名 | `测试用户` / `张小一` |
| 身份证 | 真实身份证号 | `110101********1234` |
| 医院名称 | 真实医院名 | `示例医院（测试）` |
| 医生姓名 | 真实医生名 | `示例医师` |
| 订单金额 | 真实订单金额 | `¥ 99.00`（统一示例值） |
| 订单号 | 真实订单号 | `T2026XXXXXX001` |
| 医保卡号 | 真实医保卡号 | `MC202600000001` |
| 地址 | 真实地址 | `北京市朝阳区示例路 1 号` |
| 头像 | 用户真实头像 | 系统默认头像 |

> ✅ Design 自检：交付前用上面这张表逐项核对，**任一项命中真实数据即不可交付**。

## 通用合规元素（每张截图共同要求）

- 顶部状态栏：电量、信号、时间清晰可见（建议时间统一 `09:41`）
- 页面无报错弹窗、无 loading 转圈、无空白区域
- 文案与版式与正式上线版本一致
- 所有 CTA 按钮处于可用态（未灰）
- **隐私政策链接 / 用户协议链接** 在「我的」与「下单/支付」流程中应可见
- **客服入口** 在「我的」与「订单详情」中应可见
- ICP 备案号占位（如启用 H5 落地页则需出现，小程序内可放在「关于」）

## 截图清单（8 张）

> 每张截图都需同时遵守「命名规范」「隐私脱敏」「通用合规元素」三项。

### 01 — 首页

- **文件名**：`screenshot-01-home-<device>.png`
- **页面**：小程序首页（用户登录后默认页）
- **拍摄要点**：
  - 进入首页后等首屏动画/骨架屏完全消失再截
  - 状态栏时间统一 `09:41`
  - Tab Bar 高亮「首页」
- **必须出现的元素**：
  - 主入口卡片（陪诊下单 / 服务列表）
  - 底部 Tab Bar（首页 / 订单 / 我的）
  - 顶部品牌名或 Logo
  - 至少 1 个服务分类入口
- **隐私脱敏**：用户头像用默认头像；不显示真实姓名/手机号

### 02 — 下单流程

- **文件名**：`screenshot-02-order-create-<device>.png`
- **页面**：陪诊服务下单页（填写就诊信息、选择服务）
- **拍摄要点**：
  - 表单字段全部填写完成（不要留空），便于审核员看到完整表单
  - 「提交订单」按钮处于可点击态
- **必须出现的元素**：
  - 就诊人姓名、就诊医院、就诊日期、服务类型选择
  - 价格预估区域
  - 「同意《用户协议》《隐私政策》」勾选项（**必显**）
  - 「提交订单」CTA
- **隐私脱敏**：就诊人姓名 = `测试用户`；手机号 = `138****0001`；医院 = `示例医院（测试）`；金额 = `¥ 99.00`

### 03 — 支付页

- **文件名**：`screenshot-03-payment-<device>.png`
- **页面**：订单支付页（微信支付确认前的应用内支付页）
- **拍摄要点**：
  - 不要截到微信原生支付密码键盘
  - 截「应用内支付待发起」状态
- **必须出现的元素**：
  - 订单号、金额、收款方说明
  - 支付方式：微信支付
  - 「立即支付」按钮
  - 退款/服务说明链接（合规要求）
- **隐私脱敏**：订单号 = `T2026XXXXXX001`；金额 = `¥ 99.00`

### 04 — 订单详情 / 进行中

- **文件名**：`screenshot-04-order-detail-<device>.png`
- **页面**：订单详情页（订单状态 = 进行中 / 已支付待服务）
- **拍摄要点**：
  - 选一个状态明确的订单（建议「服务进行中」或「已支付」）
  - 时间线/进度条清晰可见
- **必须出现的元素**：
  - 订单号、订单状态徽章、就诊信息
  - 陪诊师信息（姓名 + 评分，**脱敏**）
  - 「联系客服」入口
  - 「申请退款」或服务规则入口
- **隐私脱敏**：陪诊师姓名 = `示例陪诊师`；用户姓名 = `测试用户`；医院 = `示例医院（测试）`

### 05 — 钱包余额页

- **文件名**：`screenshot-05-wallet-<device>.png`
- **页面**：我的 → 钱包 / 余额页
- **拍摄要点**：
  - 余额显示一个非零的测试金额，便于审核员判断功能可用
  - 至少 2 条流水记录
- **必须出现的元素**：
  - 当前余额
  - 充值 / 提现 入口（如有）
  - 收支明细列表
  - 资金安全/规则说明链接
- **隐私脱敏**：余额 = `¥ 188.00`；流水中订单号统一 `T2026XXXXXX0NN`；不显示真实姓名

### 06 — 用户协议页

- **文件名**：`screenshot-06-terms-<device>.png`
- **页面**：用户协议（《服务协议》/《用户协议》全文页）
- **拍摄要点**：
  - 截顶部（包含标题 + 版本号 + 生效日期 + 第一段正文）
  - 滚动条位于顶部
- **必须出现的元素**：
  - 协议标题
  - 版本号 / 生效日期
  - 正文首段
  - 顶部返回按钮
- **隐私脱敏**：无个人数据，但确认协议正文不残留任何 TODO / 占位文案

### 07 — 隐私政策页

- **文件名**：`screenshot-07-privacy-<device>.png`
- **页面**：隐私政策全文页
- **拍摄要点**：
  - 截顶部（包含标题 + 版本号 + 生效日期 + 「我们收集的信息」首段）
  - 滚动条位于顶部
- **必须出现的元素**：
  - 隐私政策标题
  - 版本号 / 生效日期
  - 「我们收集的信息」章节首段
  - 顶部返回按钮
- **隐私脱敏**：无个人数据；确认未残留 TODO / 占位

### 08 — 个人中心

- **文件名**：`screenshot-08-profile-<device>.png`
- **页面**：我的（个人中心）Tab
- **拍摄要点**：
  - 已登录态
  - Tab Bar 高亮「我的」
- **必须出现的元素**：
  - 用户头像 + 昵称（**脱敏**）
  - 我的订单 / 钱包 / 客服 / 设置 入口
  - **《用户协议》《隐私政策》入口**（合规必显）
  - 「联系客服」入口
  - 版本号 / 关于我们 入口
- **隐私脱敏**：头像 = 默认头像；昵称 = `测试用户`；不显示真实手机号

## 提交方式

1. Design 按上方清单与命名规范完成 8 张真实截图，文件存放于 **本目录**（`docs/review/screenshots/`）
2. 替换对应的 `screenshot-NN-<page-key>.PLACEHOLDER.md` 占位文件（**保留 PLACEHOLDER 文件被删除**，新截图按命名规范命名）
3. 同步更新 `docs/wechat-submission-checklist.md` 末尾的「截图清单与状态」checkbox
4. 提 PR：
   - **分支**：`docs/review-screenshots-final`
   - **标题**：`docs(review): final screenshots NN-NN`（如 `docs(review): final screenshots 01-08`）
   - **描述**：列出本次新增/替换的截图编号 + 设备型号 + 自检清单（隐私脱敏 ✅ / 合规元素 ✅）
5. Reviewer 重点核对：隐私脱敏、合规元素、命名规范、清晰度
