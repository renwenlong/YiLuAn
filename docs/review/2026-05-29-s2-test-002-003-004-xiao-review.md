## ✅ 契约守门脚本 bug 修复 — 真 bug，修法对

**原 bug**：`openapi_contract_diff.py` 跨**所有** schema 要求被守字段签名一致 → 误杀 `share_scope`（请求体 `required=False` / 响应体 `required=True` 是正常 REST 设计）。

**修法**：改 `schema_name::field` 维度，请求/响应各自守。**这是对的** —— 同一字段在不同 schema 的 required 语义本就该独立。原脚本的"全局一致"假设违背 OpenAPI 语义，会让任何"请求可选/响应必填"的正常字段挂闸门。

**加分**：
1. `--update` 模式生成签名快照，baseline 可控重生
2. 脚本头注释"禁止单独改 baseline 蒙混，须改 ADR + baseline + 双签放行" —— **把契约变更流程写进守门工具本身**，防止有人偷改 baseline 绕过 review。这是架构师视角想要的"工具固化流程"
3. baseline 缺失字段视为 OK（只守已固化的不漂移）—— 渐进式守护，新增字段不误杀，正确
