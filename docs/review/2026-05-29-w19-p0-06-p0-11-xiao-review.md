### ✅ 通过

按 ADR-0037 §2.1 service 层从 `return True` → `return False` + metric + warning log 齐。逻辑硬。

### 💭 延伸优化（赞）

1. **新增 `app/observability/payment_metrics.py` 独立模块** ——而不是塞进 `payment_service.py`，复用 `reconciliation_metrics` 同模式，metric 命名空间清晰

4. **新增 `test_none_transaction_id_must_be_rejected_and_metric_incremented`** ——单测覆盖 None / empty 两种 case + metric 增量断言

### 🟡 建议（非阻塞，可在 W20 灰度前补）

**API 层早拒也应增 metric counter**。

`backend/app/api/v1/payment_callback.py:110-112`：
```python
if not trade_no:
    logger.warning("Pay callback missing trade_no: %s", data)
    return _success_response()
```

这条早拒**绕过 service 层的 PAYMENT_CALLBACK_EMPTY_TXN_TOTAL**，意味着告警仪表板会**少数 API 层早拒的回调**。两种修法：

**方案 A（推荐）**：API 层早拒也增 metric
```python
if not trade_no:
    PAYMENT_CALLBACK_EMPTY_TXN_TOTAL.labels(
        provider=provider_name, callback_type="pay"
    ).inc()
    logger.warning("Pay callback missing trade_no: %s", data)
    return _success_response()
```

**方案 B**：API 层把空 trade_no 也透传到 service 层，让 service 层统一计数（更彻底，但要改两处签名）

建议方案 A——3 行改动，灰度前保证仪表板数据完整。**这条不挡 done**，胡桃可以在 W20 实施时顺手加一个跟进 commit 或拉一个 W19 收尾 micro-PR。

### 💭 备注

ADR-0037 §2.4 提到的 Alembic CHECK 约束，胡桃这次没动是对的——`payment_callback_log` 表的 `(provider, transaction_id)` UNIQUE 约束已经隐含 NOT NULL（看 schema），加 CHECK 是多余的双重保险，反而会让 staging 历史脏数据迁移失败。**正确判断不加**。
