## §1 微信端验收（对接 S2-INT-003 / 冒烟 S2-TEST-005）

### §1.1 U-1 下单 + 支付链路验收

**支付域与业务域状态机解耦**（核心口径）：

> PaymentState 由 `/payments/wechat/callback` 推进至 `paid`；OrderStatus 保持 `created`，由陪诊师调用 accept API 推进至 `accepted`。支付域与业务域状态机解耦（待 ADR-0041 显式化）。timeline UI 显示 "已支付" 节点作为信号，不等同于业务状态切换。

验收项：

| ID | 验收点 | 通过标准 |
|---|---|---|
| §1.1.1 | U-1 折叠式分步下单（4 步同屏） | 步骤可折叠展开，摘要模板逐字符匹配钉死表（详见 U-1 wireframe），与 iOS §2.1 互锁（AC#25 任一漂移打回） |
| §1.1.2 | wxpay 支付回调 → PaymentState 推进 | `/payments/wechat/callback` 200 后，DB `Order.payment_state` = `paid`；callback 空 transaction_id 拒收（ADR-0037） |
| §1.1.3 | OrderStatus **不**因支付推进 | 支付成功后 `Order.status` 保持 `created`，由陪诊师 accept API 调用推进至 `accepted`（核 `ORDER_TRANSITIONS[created]={accepted, cancelled_by_patient, rejected_by_companion, expired}`，无 paid） |
| §1.1.4 | timeline UI 信号 | 支付成功后 timeline 显示 "已支付" 节点；OrderStatus 节点保持 "待接单" 直到陪诊师 accept |

## 附录：术语与解耦原则

- **OrderStatus**：业务域状态，`ORDER_TRANSITIONS` 钉死，支付不驱动
- **PaymentState**：支付域子状态（`none/paying/paid/failed/abnormal`），独立于 OrderStatus
- **RefundState**：退款子状态，独立
- **解耦原则**：支付/退款/业务三套状态机各管各的（Hexagonal / DDD 边界），UI 通过 timeline 拼接显示统一时间线，**严禁**为了 UI 方便而在 ORDER_TRANSITIONS 添加 paid 状态（model 注释钉死："`ORDER_TRANSITIONS` is intentionally NOT extended"）。
