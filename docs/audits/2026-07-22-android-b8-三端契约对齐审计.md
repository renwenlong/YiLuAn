## 一、Precheck 模块三端对齐(B8 核心)

| 契约点 | 安卓 | iOS | 小程序(golden) | 对齐 |
|---|---|---|---|---|
| HTTP summary | `GET users/orders/{orderId}/precheck-status` | 同 | 同 | ✅ |
| WS 通道路径 | `/ws/v1/orders/{id}/precheck`(无 /api/v1) | `/ws/v1/orders/{id}/precheck` | `/api/v1/ws/v1/orders/{id}/precheck` | ✅ 见注1 |
| WS 鉴权首帧 | `{type:auth,token}`→`auth_ok` | 同 | 同 | ✅ |
| WS 业务事件 | `precheck.status.updated`/`all_ready`/`blocked` | 同 | 同 | ✅ |
| 永久失败 close code | `[4001,4003,4004,4011]` | `[4001,4003,4004,4011]` | `[4001,4003,4004,4011]` | ✅ |
| 轮询兜底 | 5s 未 auth_ok→3s×10 | 有 | 有 | ✅ |

**注1 — WS 前缀(原 GAP-2, 降级为设计事实)**: 安卓 `PrecheckSocket` 显式 `WS_BASE_URL.replace("/api/v1/ws","/ws/v1")` — 证明 Precheck 通道后端路由挂在 `/ws/v1/...`(无 /api/v1)。iOS 同用无前缀。小程序 `precheckWs.js` 用 `/api/v1/ws/v1/...`。**安卓实现同时对齐了 iOS(precheck 无前缀) 和小程序(share 带前缀)的混合前缀约定** → 说明这是后端既定的**每通道差异化前缀**, 三端各自对了, 非对齐缺陷。已由安卓双通道实现交叉印证。

## 二、Share 模块三端对齐(B8 核心)

| 契约点 | 安卓 | iOS | 小程序(golden) | 对齐 |
|---|---|---|---|---|
| owner 创建分享 | `POST orders/{orderId}/shares` | 同 | 同(createShare) | ✅ |
| owner 列表 | `GET orders/{orderId}/shares` | 同 | 同(listShares) | ✅ |
| owner 吊销 | `DELETE orders/{orderId}/shares/{tokenId}` | 同 | 同(revokeShare) | ✅ |
| 家属请求验证码 | `POST shares/{token}/otp` | `POST shares/{token}/otp` | **无**(见 GAP-1) | ⚠️ 平台差异 |
| 换 session JWT | `POST shares/{token}/session` | 同 | 同(exchangeShareSession) | ✅ |
| 家属拉脱敏订单 | `GET shares/session/order` | 同 | 同(getShareOrder) | ✅ |
| Share WS 通道 | `/api/v1/ws/share/{token}` | `/ws/share/{token}`(ADR-0036 §2.4) | `/api/v1/ws/share/{token}` | ✅ 见注2 |
| Share WS 鉴权首帧 | `{type:share_auth,session:jwt}`→`share_auth_ok`/`share_auth_err` | 同(ShareWebSocket.swift:203/207) | 同 | ✅ 三端齐 |
| Share WS close code | 4001/4012/4013/4014 | `4001/4012/4013/4014`(token_mismatch/write_forbidden/revoked/cap) | 4011/4001/4013/4014/4002 | ✅ 见注2 |

**注2 — Share WS 前缀同 Precheck 注1**: iOS `/ws/share/...`(无 /api/v1) vs 安卓/小程序 `/api/v1/ws/share/...`, 与 Precheck 通道同为后端每通道差异化前缀约定, 三端各自对齐, 非缺陷。iOS ShareWebSocket.swift 有完整 share_auth 握手 + close code 决策(4013/4001 跳回 OTPView, 4014/4012 可重连) + 心跳测试(ShareWebSocketHeartbeatTests.swift)。

**GAP-1 — 小程序无 Share OTP 端点(已核实, 判定为平台合理差异)**:
小程序 `services/share.js` 确无 `/otp` 调用, 而是用 `wx.login` **静默授权 code** 换 share_session(见 share.js:56-74 `_wxLoginCode`)。安卓+iOS 家属端无微信静默身份, 故需 `POST shares/{token}/otp` 显式验证码换 session。**这是身份验证方式的平台差异**(微信静默 vs 手机验证码), 后端两条链路都支持 → **非缺陷, 无需补齐**。

## 三、iOS 侧发现

**(v1 GAP-3 已撤销)** — v1 误报"iOS 无 Share WS client", 经 grep 实锤纠正: **iOS Share WS 完整存在**(`ios/YiLuAn/Features/Share/Services/ShareWebSocket.swift` + `ShareWebSocketHeartbeatTests.swift` 心跳测试)。三端 Share WS(小程序/安卓/iOS)全齐, **无跟进项**。
